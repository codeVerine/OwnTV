Phase 2 i18n

Language Picker

In-app language selection wired through existing settings navigation. Depends on Phase 0's core/i18n/ runtime (already landed).

Goal

Let users pick their UI language from 22 rows (System default + 21 catalogue entries). Same-script switch is instant; cross-script triggers one Activity.recreate().

Prerequisites (all landed in Phase 0)

  • LocaleStore - SharedPreferences-backed single locale authority
  • AppLocale - context wrapping + process-level Locale/LocaleList defaults
  • LocalizedContent - provides the 4 Compose locals that make string resolution follow the selected locale:
    1. LocalResources - what stringResource() reads
    2. LocalContext - must match Resources (painters read both)
    3. LocalConfiguration - registers invalidation dependency
    4. LocalLayoutDirection - must be set manually for RTL
    Also handles script-family detection and triggers Activity.recreate() when crossing script boundaries (e.g. Latin to Arabic).
  • SupportedLocales - generated catalogue from locales.json (21 entries, only en-US currently packaged)

Q: What happens on first launch if the device language is not English?

Today (before translations ship): App shows English regardless. No translations exist yet, so Android's resource fallback always picks the source values/ (English). The stored locale tag defaults to "" (follow system), but "follow system" only matters when translated resources exist for that system locale.

After Phase 4 (translations shipped, flags flipped): If the device is set to e.g. French and fr is packaged, the app auto-launches in French with no user action. The "" default means "follow device". Android resolves values-fr/ resources automatically via attachBaseContext wrapping. If the device locale isn't in our 21-language catalogue, fallback chain applies (e.g. pt-PT falls to pt if we have it, then to English).

This is standard Android resource fallback. Phase 2 itself doesn't change this behavior - it adds the picker so users can override the device language within OwnTV.

Coverage Badge: What It Is & Future Contribution Ideas

The % badge shows translation coverage - what percentage of the source English strings have a translation in that locale. Computed by gen_supported_locales.py at build time from the actual resource files.

Future idea (not Phase 2 scope - discuss for Phase 4 or later)

Contribution CTA when coverage < 100%

  • If coverage < 100%, show a small "Help translate" link or icon
  • Opens Weblate URL for that locale directly
  • Since this is an Android TV app, could show a QR code that opens Weblate on the user's phone
  • Could also show it in the Companion web UI (phone-facing) for even easier access

Where this fits in the plan

  • Phase 2 ships the picker with coverage % as a read-only badge
  • Phase 4b sets up Weblate - contribution URLs only exist after that
  • A "Help translate" CTA naturally belongs after 4b, as a follow-up
  • QR code for Weblate is a nice addition to Companion HTML (Phase 1 batch 10)

This is worth adding to the roadmap but not blocking Phase 2 on it. We can discuss the exact UX (QR code? Companion link? Both?) once Weblate is live.

Icon Choice: Translate vs Globe

Translate (A文)
Google's Material "translate" icon. Used by Google Translate, Chrome translate bar, Android Settings > System > Language. Most recognizable for language switching.
Recommended
🌐
Globe
Facebook, Apple's language selector. More generic - also used for "web", "international", "network". Could be confused with network/internet settings.
Globe with meridians
More detailed globe. Still generic but more distinct from simple network icons. Used by some i18n libraries.

All existing OwnTV icons are custom Canvas-drawn paths (no emoji, no Material lib dependency). Whichever icon we pick, it gets drawn as a Canvas path in OwnTVIcon.kt. Google's "translate" icon is the industry standard for language settings.

Sorting Order

1 "System default" pinned first (tag = "")
2 Remaining rows A-Z by endonym (native name in its own script)
Plan mentions "recently used" between pinned and A-Z. Skipping this for now - 22 rows is small enough that recency adds complexity without clear benefit. Can revisit.

Font Handling

Endonyms render with FontFamily.SansSerif, never bundled Lora. This is critical: Lora has no CJK, Arabic, Hebrew, Indic, or Thai glyphs. SansSerif uses the platform's Noto fallback stack which covers all scripts.

English name and coverage badge can use the app's normal font since they're always Latin.

Visibility Filter

Only rows where packaged = true AND pickerVisible = true appear. Currently only en-US meets both. All other entries have packaged = false, pickerVisible = false.

This means Phase 2 ships with a functioning picker that shows only English + System default until Phase 4 flips the flags. The picker infrastructure is ready but not prematurely exposed.

Script-Change Behavior

Same script (Latin to Latin, e.g. English to French): Instant. LocalizedContent updates Compose locals, full subtree recomposes.

Cross script (Latin to Arab, e.g. English to Arabic): One Activity.recreate(). LocalLocaleList is @RestrictTo and can't be overridden, so CJK/RTL font shaping needs a fresh Activity context.

Already handled by LocalizedContent's sameScriptFamily() check.

ViewModel Shape

class LanguageSettingsViewModel(
    private val localeStore: LocaleStore,
) : ViewModel() {

    val currentTag: StateFlow<String> = localeStore.currentTag

    val pickerRows: List<SupportedLocale> =
        SupportedLocales.pickerRows.sortedBy { it.endonym.lowercase() }

    fun setLocale(tag: String) {
        viewModelScope.launch { localeStore.set(tag) }
    }
}

Thin by design. LocaleStore does all persistence and process-level locale application. SupportedLocales.pickerRows handles the packaged+visible filter. ViewModel just bridges the picker UI to the store.

Risks & Edge Cases

Only English visible on ship. Since only en-US has packaged=true, pickerVisible=true, the picker shows 2 rows (System default + English). This is correct per plan - the picker ships ready but doesn't expose untranslated locales. Phase 4 flips the flags.
No "recently used" sorting. Plan mentions it. With 22 max rows it adds complexity for minimal benefit. Omitting for now - trivially addable later (persist last-3 tags in LocaleStore, sort them between pinned and alphabetical).
Search filtering at this size. Useful for non-Latin endonyms (typing "jap" finds "日本語"), but optional. Including it since the SearchBar component already exists and is one line to add.
D-pad focus on recreate. After a script-change recreate, focus returns to the settings root (recreate kills the picker's state). Acceptable - the language already changed, user sees the result. No special handling needed.
